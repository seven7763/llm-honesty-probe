# llm-honesty-probe (по-русски)

**Небольшой нейтральный CLI без зависимостей, который даёт *сигналы* о том,
отдаёт ли OpenAI-/Anthropic-совместимый эндпоинт именно ту модель, которую
заявляет, — или тихо занижает её.**

> **Сначала прочтите это — что это и чего это НЕ делает.**
> Инструмент выдаёт **эвристические сигналы, а не доказательство.** Снаружи
> невозможно криптографически доказать, какие веса крутит провайдер. Но можно
> собрать воспроизводимые поведенческие улики, которые ловят типичные подмены
> (замена модели, жёсткая квантизация, обрезка контекста, тихий fallback).
> Спокойный прогон — это *обнадёживает*, но не гарантия; флаг — это *повод
> присмотреться*, а не приговор. Раздел [Ограничения](#ограничения) — не формальность.

- **Ноль рантайм-зависимостей** — только стандартная библиотека Python. Нечего
  `pip install`, нечего проверять в lock-файле. Склонируйте и прочитайте код.
- **Ключ API никогда не печатается, не логируется и не сохраняется.** Он читается
  **только** из переменной окружения (флага `--key` намеренно нет), а весь вывод
  проходит через слой редактирования.
- **Намеренно нейтрален.** Направьте его на кого угодно — на проверяемый релей, на
  официальный API, на локальный сервер моделей или на шлюз, который делают авторы
  (см. [Раскрытие](#раскрытие)). Инструменту всё равно, кого вы тестируете.

## Зачем это нужно

У дешёвых релеев "GPT / Claude / DeepSeek" есть незаявленная проблема доверия:
некоторые тихо подменяют модель на меньшую, квантованную или с обрезанным
контекстом — и часто это начинается через недели, когда вы перестали проверять.
А очевидная проверка не работает:

> **Спрашивать модель «какая ты модель?» бесполезно** — ответ идёт из системного
> промпта/дообучения и легко подделывается. Тестируйте **способности и поведение**,
> а не самоотчёт.

## Установка и запуск

```bash
git clone https://github.com/seven7763/llm-honesty-probe
cd llm-honesty-probe
python3 -m llm_honesty_probe --self-test          # прогон по встроенному моку, ключ не нужен

export OPENAI_API_KEY="sk-...ваш ключ..."         # только из окружения, не в истории команд

# Один эндпоинт
python3 -m llm_honesty_probe --base-url https://провайдер/v1 --claimed-model gpt-4o

# Дифф (самый сильный режим): сравнить релей с официальным API
python3 -m llm_honesty_probe \
  --base-url https://релей/v1 --claimed-model gpt-4o \
  --compare-base-url https://api.openai.com/v1 --compare-model gpt-4o \
  --compare-api-key-env OPENAI_API_KEY_OFFICIAL
```

## Методология (кратко)

- **Отпечаток токенизатора.** Разные семейства моделей используют разные
  токенизаторы, и это «просвечивает» через `usage.prompt_tokens`. Мы измеряем
  число токенов на батарее строк и берём *дельту* относительно якоря, чтобы убрать
  накладные расходы шаблона чата. Режим `--compare` (сравнение с эталонным
  эндпоинтом) самый надёжный; для одного эндпоинта — сверка с таблицей эталонов из
  `tiktoken` (`cl100k_base` / `o200k_base`). Нет эталона для семейства — вывод
  «неопределённо», без догадок.
- **Порог способностей.** Задачи с **заранее известным правильным ответом**
  (многошаговая арифметика, разворот строки, подсчёт) + строгий JSON + поведение
  отказа на безобидном запросе. Флагман проходит легко; заниженный/квантованный
  дублёр чаще спотыкается. Провалу мы даём больший вес.
- **Длинный контекст.** Прячем уникальную парольную фразу в длинном тексте и просим
  её вернуть — **иглу кладёт сам инструмент, ответ известен**. Работает на коротком
  контексте, ломается на длинном — типичный признак **тихой обрезки**.
- **Стабильность и производительность.** Повтор одного запроса N раз: детерминизм
  при `temperature=0`, стабильность поля `model` и `system_fingerprint`, а также
  p50/p95 задержки и доля ошибок (справочно).
- **Самоотчёт** (низкий вес): спрашиваем модель, кто она, и сверяем с заявленной —
  только потому, что *отсутствие* такой проверки было бы подозрительным; легко
  подделать, поэтому уверенность ограничена «low».

## Ограничения

- **Это сигналы, а не доказательство** — веса криптографически не доказать.
- **Набор проб мал и субъективен** — знающий пробы провайдер может подстроиться;
  поэтому сильнейший режим — ваш собственный дифф, и PR с более «неподделываемыми»
  пробами приветствуются.
- **Учёт токенов различается** — кто-то не возвращает `usage`, оценивает его или
  считает с особенностями; проба токенизатора работает с допуском и скорее скажет
  «неопределённо», чем обвинит.
- **`temperature=0` не гарантирует детерминизм**, поэтому этот сигнал намеренно
  низкой уверенности.
- **У «подозрительно» бывают честные причины** — меньшая модель может быть тем, что
  вы и просили; короткий контекст — реальным лимитом. Используйте `--compare`.

## Безопасность ключа

Ключ читается только из переменной окружения, указанной в `--api-key-env` (по
умолчанию `OPENAI_API_KEY` / `ANTHROPIC_API_KEY`); флага `--key` нет; ни один путь
кода не печатает ключ или заголовок `Authorization`; весь вывод проходит через
`redact()`. Для аудита смотрите `llm_honesty_probe/redaction.py` и `client.py`.

## Раскрытие

Проект начали люди, работающие над **daoxe** — OpenAI-совместимым LLM-шлюзом (он
также нативно поддерживает Anthropic Messages для Claude Code). Мы сделали его,
потому что предпочитаем, чтобы вы **проверяли** провайдера, а не верили на слово —
включая нас. Направьте инструмент на daoxe и на то, чем пользуетесь сейчас, и
сравните:
[daoxe.com](https://daoxe.com/?utm_source=github&utm_medium=organic&utm_campaign=ru_launch).
daoxe поощряет такие проверки; если он их не пройдёт — это баг-репорт, который мы
хотим получить. Полезность инструмента не зависит от daoxe и ничем его не выделяет.
